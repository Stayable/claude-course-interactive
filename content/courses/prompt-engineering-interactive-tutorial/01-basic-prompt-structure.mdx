# Chapter 1: Basic prompt structure

A call to the Claude Messages API has three required pieces and a few useful optional ones. Once you've seen them once, every prompt you'll ever write is a variation on this skeleton.

## The required pieces

<Diagram
  takeaway="Three pieces are required: model, max_tokens, messages. The messages array alternates user/assistant turns, starting with user."
  chart={`flowchart LR
    API[messages.create] --> M[model]
    API --> T[max_tokens]
    API --> Msgs[messages array]
    API -.-> Sys[system prompt]
    API -.-> Temp[temperature]
    Msgs --> U1[user]
    Msgs --> A1[assistant]
    Msgs --> U2[user]
    Msgs --> A2[...]`}
/>

- **`model`** — the model id (e.g. `claude-sonnet-4-6`).
- **`max_tokens`** — a hard cap on how many tokens Claude will generate. Set it high enough that you don't get cut off mid-sentence.
- **`messages`** — an alternating list of `{role: "user" | "assistant", content: "..."}`. The **first** message must be `user`. Roles must alternate (no two user messages in a row).

Optional but high-leverage:

- **`system`** — a separate parameter (not a message) that gives Claude context, persona, or rules *before* the conversation starts.
- **`temperature`** — variability in the reply. `0` is deterministic-ish; higher means more variation. For learning, start at `0`.

## A first request

Below is exactly the shape of a minimal call.

```python
client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=2000,
    temperature=0.0,
    system="",
    messages=[
        {"role": "user", "content": "Hi Claude, how are you?"}
    ]
)
```

## Common malformed prompts

Two failure modes catch most newcomers. Both will error out before Claude even sees the message.

## System prompts

A system prompt lives outside the `messages` array. It sets the stage: *who* Claude is and *how* it should respond. The same user message can produce wildly different replies depending on the system prompt.

<Playground
  label="No system prompt — straight answer"
  initialPrompt="Why is the sky blue?"
/>

<Playground
  label="With system prompt — Socratic questioning"
  system="Your answer should always be a series of critical thinking questions that further the conversation (do not provide answers to your questions). Do not actually answer the user question."
  initialPrompt="Why is the sky blue?"
/>

The user message is identical. The system prompt changes everything.
