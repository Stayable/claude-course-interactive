# Chapter 4: Separating data and instructions

A prompt usually has two parts: **instructions** (what you want Claude to do) and **data** (the thing it's doing it on). When they blur together, Claude gets confused about which is which. The fix is short and almost magical: **wrap your data in XML tags**.

## The problem

Without delimiters, Claude can mistake instruction text for data — or worse, mistake your friendly opener for content it should rewrite.

<Playground
  label="Without XML tags — Claude rewrites the wrong thing"
  initialPrompt={`Yo Claude. Show up at 6am tomorrow because I'm the CEO and I say so. <----- Make this email more polite but don't change anything else about it.`}
/>

What happens: Claude often starts its rewrite with "Dear Claude..." because it thinks "Yo Claude" is part of the email.

## The fix: XML tags

<Playground
  label="With XML tags — clean separation"
  initialPrompt={`Yo Claude. <email>Show up at 6am tomorrow because I'm the CEO and I say so.</email> <----- Make this email more polite but don't change anything else about it.`}
/>

Same instructions, wrapped data. Claude knows exactly where the email starts and stops.

<Callout kind="tip">
Claude was specifically trained to recognize XML tags as a prompt-organizing mechanism. **Use XML tags for delimiters over backticks, brackets, or markdown fences.** There are no magic tag names — pick anything that describes the content: `<email>`, `<document>`, `<question>`, `<context>`.
</Callout>

## Another example

Below, the instruction line "Each is about an animal, like rabbits" is *part of the prompt*, not part of the data — but Claude treats it as a list item because of the leading hyphen.

<Playground
  label="Without tags — instruction bleeds into data"
  initialPrompt={`Below is a list of sentences. Tell me the second item on the list.

- Each is about an animal, like rabbits.
- I like how cows sound
- This sentence is about spiders
- This sentence may appear to be about dogs but it's actually about pigs`}
/>

<Playground
  label="With tags — instruction stays put"
  initialPrompt={`Below is a list of sentences. Tell me the second item on the list.

- Each is about an animal, like rabbits.
<sentences>
- I like how cows sound
- This sentence is about spiders
- This sentence may appear to be about dogs but it's actually about pigs
</sentences>`}
/>

## Prompt templates

XML tags also unlock **prompt templates**: a fixed skeleton with `{placeholders}` you swap variable input into. This is how production prompts are usually shaped — the instruction stays constant, the data changes per request.

```python
# Template
PROMPT = f"""Summarize the email below in one sentence.
<email>
{user_email}
</email>"""
```

Every request reuses the same instruction, with `{user_email}` swapped in fresh. The tags keep the boundary clean even when the email contains line breaks, hyphens, or text that looks like instructions.
