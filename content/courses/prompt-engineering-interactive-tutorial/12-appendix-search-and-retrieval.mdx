# Appendix 10.3: Search & retrieval

Claude's training data is fixed. Yesterday's announcement, your internal wiki, this morning's customer ticket — none of it is in the model. The way to bring that material into the conversation is **search and retrieval**: find the relevant snippets first, then hand them to Claude as context.

This pattern goes by a few names. The most common one is **RAG** — Retrieval-Augmented Generation.

## The shape

  takeaway="Retrieval finds the right pieces. Claude reads them and answers, with citations."

Three jobs are happening:

1. **Indexing** *(before any question is asked)*. Break your corpus into chunks, generate embeddings or build a search index, store them.
2. **Retrieval** *(per question)*. Find the top-k chunks most likely to contain the answer.
3. **Generation** *(per question)*. Hand the chunks to Claude inside `<document>` tags and ask the question.

## A skeleton prompt for RAG

This is the prompt template that pairs well with any retriever — it borrows every technique from earlier chapters.

```
You are a careful assistant. Answer the user's question using ONLY
the provided documents. If the documents don't contain the answer,
say so.

<documents>
<document id="1">{chunk_1}</document>
<document id="2">{chunk_2}</document>
<document id="3">{chunk_3}</document>
</documents>

First, extract any quotes from the documents relevant to the
question into <quotes></quotes> tags, each prefixed with [id=N]
showing which document it came from.

If there are no relevant quotes, write "no relevant quotes found".

Then, write your answer in <answer></answer> tags. Cite documents
inline like [1] or [2]. If quotes don't support an answer, say
you can't answer from the provided documents.

<question>{user_question}</question>
```

It hits: role (1), task context (2), input data with clear tags (6), rules + out (4), precognition (8 — extract quotes first), output format (9 — `<answer>` with citations), and prefill-friendly structure (10).

## What controls quality

The retriever often matters more than the model. If retrieval pulls the wrong chunks, Claude can't recover — it can only answer using what it sees.

Things that move the needle on retrieval quality:

- **Chunk size.** Too small → loses context. Too large → noisy, wastes tokens. Paragraph-to-section size is usually right.
- **Hybrid search.** Embeddings *plus* keyword search catches what each one misses.
- **Reranking.** Run a fast first pass (vector or keyword), then a slower, smarter rerank on the top 20 to pick the final 3–5.
- **Filtering.** Constrain by date, source, permission *before* generation, not after.
