# Introduction to projects

A **Project** is a folder for your conversations with Claude. Everything inside it shares the same context — the same documents, the same instructions, the same shared memory of what's been discussed. New chats inside a Project start *informed*, not blank.

The shape is simple:

## When to make a Project

Make a Project the moment you notice yourself:

- Pasting the same brief or background into every new chat
- Re-explaining your company, your role, or your customer to Claude every time
- Wanting Claude to remember a long document across multiple sessions
- Working on something that'll take more than a day

A one-off task doesn't need a Project. Anything you'll come back to does.

## What goes inside

Two things, both optional but powerful:

1. **Instructions.** A short note Claude reads at the top of every chat. *"I'm a marketing manager at a B2B SaaS company. We sell to mid-market HR teams. Default to plain language, no jargon."* Two or three sentences is usually enough.
2. **Files.** PDFs, docs, slides, transcripts — anything Claude should know. The brand guide. The product brief. Customer interview notes. They stay attached to the Project.

## Projects vs. one long chat

These two solve different problems.

- A **long chat** carries context *within one thread*. Great while you're in flow. Not searchable later.
- A **Project** carries context *across many threads*. You can start a fresh chat anytime and Claude is already up to speed.

If you've been pasting the same paragraph into 10 chats this week, you needed a Project ten chats ago.
