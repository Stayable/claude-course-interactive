# Creating with artifacts

Sometimes the answer is a sentence. Sometimes it's a *thing* — a document, a piece of code, a chart, a webpage. When the output is a thing, Claude can put it in its own panel next to the chat: an **artifact**.

You keep talking in the chat. The artifact updates in place. You can copy it, download it, or hand it to someone.

## When Claude pops an artifact

Claude reaches for an artifact when the output is:

- **Longer than a few paragraphs** and you'll want to read or edit it as one piece
- **Self-contained** — a draft, a script, a single HTML page, a structured outline
- **Something you'll likely revise** — a resume, a proposal, a piece of code

You can also ask for one explicitly: *"Put this in an artifact."* Or the opposite: *"Just answer in the chat — no artifact."*

## Working an artifact

The flow is small and worth getting muscle memory for:

1. **Ask** for the thing. *"Draft a one-page proposal for…"*
2. **Read** it in the artifact panel.
3. **Talk** to the chat about what to change. *"Cut the intro. Move the budget table up. Make the tone less formal."*
4. **Watch** the artifact update in place.
5. **Copy or download** when it's right.

You don't need to repaste the document each round. Claude is editing the artifact directly.
