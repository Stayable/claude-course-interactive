# The tool-use loop

Tool use lets Claude call functions you define — to look things up, run code, or take actions. The shape of the interaction is a small loop: you send a message and a list of tools, Claude either replies or asks to call a tool, you run the tool, you send the result back, and Claude continues.

<Callout kind="note">
This lesson assumes you've made at least one Claude API call. If you haven't, do the **Claude with the Claude API** course first.
</Callout>

## The loop, drawn

<Diagram
  takeaway="Tool use is a turn-based loop. You only stop when Claude returns a message with stop_reason='end_turn'."
  chart={`sequenceDiagram
    participant U as Your app
    participant C as Claude
    participant T as Tool (your code)
    U->>C: messages + tools[]
    C-->>U: stop_reason=tool_use, tool_use block
    U->>T: run tool with input
    T-->>U: tool result
    U->>C: append tool_result, send again
    C-->>U: stop_reason=end_turn, final message`}
/>

The two states that matter:

- `stop_reason: "tool_use"` — Claude wants you to run a tool. Look at the `tool_use` block, run it, append a `tool_result` to the messages list, and send again.
- `stop_reason: "end_turn"` — Claude is done. Show the message.

## Defining a tool

A tool is a name, a description, and a JSON schema for its input. Claude reads the description and decides when to call it, so the description is doing real work — write it like documentation, not a label.

```json
{
  "name": "get_weather",
  "description": "Get current weather for a city. Returns temperature in Celsius.",
  "input_schema": {
    "type": "object",
    "properties": {
      "city": { "type": "string", "description": "City name, e.g. 'Boca Raton'" }
    },
    "required": ["city"]
  }
}
```
